# ⚡ 한정판 굿즈 / 스니커즈 타임세일 선착순 구매 서비스

클라우드 컴퓨팅 과제 제출을 위한 AWS 배포 및 기능 검증 프로젝트입니다. 본 서비스는 매일 정해진 시간에 접속이 폭증하는 한정판 타임세일 시나리오를 가정하여 개발되었습니다.

---

## 1. 서비스 소개
* **대상 사용자:** 한정판 스니커즈 및 굿즈를 구매하려는 온라인 쇼핑 이용자
* **해결하려는 문제:** 특정 시간에 사용자가 일시에 몰릴 때 발생하는 재고 동시성 문제와 서버 부하를 제어하고, 선착순 접수를 공정하게 처리합니다.
* **핵심 기능 (3가지):**
  1. **타임딜 상품 및 잔여 재고 조회:** 현재 진행 중인 한정판 상품 목록과 실시간 잔여 수량 확인
  2. **선착순 굿즈 구매 신청:** 구매자 정보와 함께 구매 버튼을 클릭하여 선착순 접수 및 실시간 재고 차감 (트래픽 집중 기능)
  3. **주문 접수 내역 조회:** 본인의 이름으로 주문 번호와 접수 상태 조회

---

## 2. AWS 구성도 및 서비스 선택 이유
* **사용자 요청 경로:** `브라우저 (Client) ➔ AWS EC2 (Nginx + Flask 백엔드 컨테이너) ➔ 메모리 데이터베이스`
* **사용한 AWS 서비스:** **AWS EC2 (Elastic Compute Cloud)**
  * **선택 이유:** Docker Compose를 활용해 로컬에서 검증한 컨테이너 환경을 AWS 가상 서버에 그대로 이식할 수 있으며, 소규모 트래픽 테스트와 배포 검증을 가장 빠르고 안정적으로 수행할 수 있기 때문입니다.

---

## 3. 실행 및 배포 방법
* **준비 사항:** AWS EC2 인스턴스 (Ubuntu 22.04), 보안 그룹 설정 (`80`, `5000` 포트 개방), Docker 및 Docker Compose 설치
* **로컬 실행 명령:**
  ```bash
  docker compose up -d --build
  ```
* **AWS 배포 절차:**
  1. EC2 서버에 프로젝트 소스코드 클론 및 이동
  2. `docker compose up -d --build` 명령어 실행으로 컨테이너 백그라운드 배포
* **포트 및 접속 주소:**
  * 접속 포트: `5000`
  * 배포 주소: `http://<EC2-퍼블릭-IP>:5000`

## 4. 기능별 시험 결과 기록지 (정상 / 경계 시험)

### 기능 1: 타임딜 상품 및 잔여 재고 조회
* **정상 시험**
  * **시험 환경:** 클라이언트 웹 브라우저, 상품이 정상 등록된 상태
  * **입력:** 메인 페이지 접속 및 상품 목록 조회
  * **기대 결과:** 한정판 상품명, 가격, 실시간 잔여 수량이 표 형태로 정확히 출력됨
  * **실제 결과:** 서버에 저장된 상품 정보와 잔여 수량이 화면에 정상 렌더링됨 (정상)
* **경계/실패 시험**
  * **시험 환경:** 재고가 완전히 소진된 상품이 존재하는 상태
  * **입력:** 재고가 0인 상품의 상세 상태 조회 요청
  * **기대 결과:** 재고 소진 상태가 반영되어 품절 상태로 표시됨
  * **실제 결과:** 잔여 재고 0개 상태가 정확히 출력됨 (정상)

### 기능 2: 선착순 굿즈 구매 신청 (트래픽 집중 기능)
* **정상 시험**
  * **시험 환경:** 타임딜 오픈 시간대, 재고가 남아있는 상태
  * **입력:** 구매자명: "홍길동", 연락처: "010-1234-5678", 상품 선택 후 구매 신청 클릭
  * **기대 결과:** "주문이 성공적으로 접수되었습니다" 메시지 출력 및 잔여 재고 차감
  * **실제 결과:** 재고가 1개 정상 차감되고 주문 번호와 성공 메시지가 출력됨 (정상)
* **경계/실패 시험**
  * **시험 환경:** 잔여 재고가 모두 소진된 직후의 상태
  * **입력:** 재고가 0인 상태에서 추가 구매 신청 시도
  * **기대 결과:** "재고가 모두 소진되었습니다 (품절)" 경고 알림 출력 및 주문 차단
  * **실제 결과:** 예외 처리가 작동하여 추가 구매 접수가 완벽히 차단됨 (정상)

### 기능 3: 주문 접수 내역 조회
* **정상 시험**
  * **시험 환경:** 정상적으로 구매 주문이 접수된 상태
  * **입력:** 조회 폼에 주문자 이름("홍길동") 입력 후 조회 버튼 클릭
  * **기대 결과:** 해당 주문의 상품명, 주문자 정보, 처리 상태('주문 완료')가 상세히 출력됨
  * **실제 결과:** 일치하는 주문 데이터를 정확히 찾아 화면에 목록으로 출력함 (정상)
* **경계/실패 시험**
  * **시험 환경:** 존재하지 않는 주문 정보를 검색하는 상태
  * **입력:** 시스템에 등록되지 않은 이름("김철수") 입력 후 조회
  * **기대 결과:** "조회된 주문 내역이 없습니다." 안내 메시지 출력
  * **실제 결과:** 예외 처리 로직이 작동하여 오류 없이 안내 문구가 출력됨 (정상)

## 5. 확장 검토 (ELB 및 Auto Scaling)
* **적용 여부:** 미적용 (단일 EC2 인스턴스 구축)
* **판단 근거:** 본 프로젝트는 소규모 기능 검증 및 실습용으로 평상시 트래픽이 적어 단일 EC2 인스턴스로 충분합니다. 다만, 실제 대규모 한정판 발매 플랫폼처럼 수만 명의 사용자가 정각에 동시에 몰리는 상황에서는 **AWS ALB (Application Load Balancer)**를 통해 인입 트래픽을 다중 백엔드 서버로 분산하고, **Auto Scaling 그룹**을 도입하여 서버 인스턴스를 자동으로 확장해야 합니다. 또한 동시성 이슈 해결을 위해 **Redis** 기반의 인메모리 재고 관리 시스템 도입을 검토할 수 있습니다.
